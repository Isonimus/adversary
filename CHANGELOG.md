## 2026-10-25 (v0.6.0-alpha)
- **The screen now sleeps on idle to save battery.** After a period of inactivity the display dims to a still-readable level, then turns off; any key wakes it. Both delays are configurable in Settings > Display (Dim After / Screen Off), and the dim stage is a readable intermediate so a glance does not require a keypress. (slices 0115, 0117; ADR-0114, ADR-0116)
- **Clocks show your local time.** Set a UTC offset in Settings > Time Zone and the wardriving clock and on-screen times render local, while saved logs and exports stay in UTC so captures remain comparable across devices. (slice-0119; ADR-0118)
- **Actions that need an SD card grey out when none is in.** Rebuild Index no longer runs a scan that reports a false success with no card present; it reads as disabled until a card is inserted, matching the rest of the SD-gated menu. (slice-0042)
- **Wardriving radio mode is chosen per run from the idle screen.** The WiFi / BLE / both selector sits on the pre-run screen, so each session picks its radios without a trip into Settings. (slice-0112; ADR-0111)
- **A what's-new screen shows once after an update.** The first boot on a new version opens a short summary of what changed; reopen it any time from Settings > What's New. The version is shown live from the build, so the notes never carry a stale number. (slices 0122, 0124; ADR-0121)
- **Handshake Auto Hunt describes itself accurately.** The config screen no longer claims Auto Hunt "uses values from the Settings menu": its timing is built in and the whitelist is its only Settings input, which the copy now states. (slice-0123; ADR-0111)

## 2026-10-23 (v0.5.0-alpha)
- **One model behind every attack-config screen.** Deauth, Evil Twin, Karma, Probe Flood, Beacon Spam and Handshake now share the same config form: identical row chrome (label left, value right), the same selection and scrolling behaviour as the lists, one green start-button style, and one keyboard model for navigating, editing values and activating a row. (slices 0097, 0106, 0108; ADR-0092, 0096, 0107)
- **Handshake is now two screens: Auto Hunt and Manual.** The mode is chosen from the Wireless -> Handshake menu instead of toggled inside the screen, so each presents only the controls it needs. (slice-0095; ADR-0094)
- **Deauth and Handshake Manual take their target from the scanner.** The Target row shows `(select from scanner)` until set; selecting it opens the WiFi scanner and returns with the chosen AP. Manual capture shows the target SSID, channel and BSSID on the capturing screen. (slices 0109, 0110)
- **Destructive confirms are consistent everywhere.** Every delete / clear / discard / forget prompt now routes through one shared confirm dialog. (ADR-0085)
- **Menus grouped by purpose, with a unified footer style.** The Wireless and BLE menus are banded into Recon / Attacks / Data sections, and footer hints and key glyphs follow one house style across the UI. (slices 0099, 0101)
- **New Tron electric-cyan theme preset.** (slice-0102)
- **Wardriving is steadier in BOTH (WiFi+BLE) mode.** A fixed-size Bloom filter bounds deduplication memory and a passive BLE scan flattens the heap-usage slope, so long BOTH-mode sessions no longer trend toward out-of-memory; the live log reserves per-type slots and the network count survives Stop for the save screen. (ADR-0103)
- **Optional heap-fragmentation readout.** The heap badge can show the largest free block alongside free heap, the tell that classified the BOTH-mode OOM. (ADR-0103)
- **Sniffer capture controls moved into a config block** for a consistent setup flow before capture.

## 2026-10-19 (v0.4.0-alpha)
- **Wardriving now observes BLE as well as WiFi.** A BLE observation source feeds both the live network log and the WiGLE CSV export, selectable with a radio-mode setting (WiFi / BLE / both); deduplication is type-aware so a WiFi AP and a BLE peripheral never collapse into one row. WiFi and BLE run at the same time via radio coexistence. (slices 0061, 0075; ADR-0060)
- **Sniffer capture no longer corrupts the heap.** The WiFi-driver-task callback mutated containers the main loop also touched with no synchronization, so under load the dual-core chip smashed allocator metadata and rebooted (`CORRUPT HEAP`), usually caught on exit-to-menu. Each frame is now copied into a POD and handed to the main loop over a FreeRTOS queue, which does all stats/log/pcap work on one task. (slice-0078)
- **Packet log reads cleanly under heavy traffic.** Scrolling up off the newest row freezes the log so it stays readable at any packet rate (stats, flood detection and capture keep running), and the log renders in capture order after its ring buffer wraps. (slices 0070, 0071)
- **Release firmware runs quiet.** A level-gated logging layer and a dedicated release build ship the image at WARN, so the serial console is no longer flooded at runtime. (ADR-0051)
- **One shared component behind every list and popup menu.** The scanner, sniffer, wardriving, captures, RFID, radio, BLE, settings and handshake-history lists, and all eight quick-action popups, now route through a single list/menu component, so navigation, scrolling and the selected-row highlight are consistent across the whole UI. (slices 0062-0077)
- **Evil Twin lists every connected client.** The clients view no longer drops entries. (slice-0076)

## 2026-10-11 (v0.3.0-alpha)
- **RFID Write / clone.** Restore a saved `.nfc` dump onto a MIFARE Classic 1K card — all 47 data blocks written back with the recovered keys (Key A → Key B → factory-FF fallback), with a per-block write-retry so a transient RF warm-up can't drop a block on the first pass. Every outcome is reported (blocks written, auth failures, write failures); nothing is silently skipped. (slices 0043, 0046, 0047)
- **UID cloning on magic cards.** The opt-in UID write now lands block 0 on both card families: a Gen2/CUID direct write, and — falling through when that is refused — the Gen1a backdoor. The firmware reports which card type it detected; an ordinary card's locked UID is reported plainly, not masked. Verified end-to-end on a Gen1a card (UID written, read back, then restored). (slice-0048)
- **Reliable Gen1a magic detection and sector reads.** Detection retries the timing-sensitive backdoor probe so a magic card is not missed on the first try; the audit read path authenticates once per sector (the fix for sectors reading back as `??`) and names every read/auth failure instead of failing silently. (slices 0044, 0045, 0046)
- **Dashboard web AP is WPA2-protected.** The on-device dashboard access point now uses an auto-generated per-device key instead of being open. (#45)
- **Sniffer capture survives an attack handoff.** WiFi is re-initialised on sniffer start, so launching a capture after an attack no longer comes up dead. (#52)
- **Root-menu list items live-gate on Re-scan.** Menu entries for a module seated after boot (RFID, Wardriving, Captures, BadBLE) un-grey as soon as a Re-scan finds the hardware, no reboot. (slice-0042)

## 2026-09-23 (v0.2.0-alpha)
- **Captured credentials are no longer printed to the serial console.** The captive-portal login handler logged harvested usernames and passwords in cleartext via an unconditional `Serial.printf`; it now logs only a secret-free capture count, and the leftover debug pointer prints were removed. (slice-0035)
- **Screenshots save reliably from memory-heavy screens.** Fn+S now streams the BMP to SD row-by-row instead of allocating the whole ~97 KB file at once, so a capture from a full Scanner or Sniffer list no longer fails with an out-of-memory error on the no-PSRAM device. (slice-0034)
- **Screenshot capture (Fn+S).** Press Fn+S on any screen to save a BMP of the current display to `/adversary/screenshots/`. *(First appearance in this log; shipped earlier.)*
- **SD-gated menu entries are greyed out when no card is present**, so unavailable actions (captures, dashboard, wardriving export, API-key import, logs) read as disabled rather than failing only after you select them. *(First appearance in this log; shipped earlier.)*
- **Boots gracefully with no SD card.** The device no longer requires a card to start; SD-dependent actions degrade with a toast + retry instead of blocking boot. *(First appearance in this log; shipped earlier.)*

## 2026-09-10
- **Sub-GHz FSK capture & replay (CC1101).** FSK-demodulated capture (2-FSK / GFSK / MSK) for constant-amplitude remotes the OOK envelope-slicer can't demodulate, chosen from a table of common modem presets (deviation / data rate / RX bandwidth, which can't be inferred from an unknown signal). Reuses the RMT edge-timing path (the FSK demod drives GDO0 with recovered NRZ just like the OOK slicer), with a new `SUB2` on-SD format carrying the modulation descriptor so a captured signal replays under its own configuration; existing OOK `.sub` files keep loading unchanged. MSK below the CC1101 ~26 kBaud floor is rejected, not mis-tuned; 4-FSK is detect-only (no raw path on this silicon). The register math (deviation/data-rate/RX-bandwidth) is native-tested and cross-checked against the OOK block's own registers; the on-device capture/replay round-trip against a controlled 2-FSK source is a tracked follow-up. Second phase of slice-0019. The Radio menu's "Capture" is now "OOK Capture".
- **Sub-GHz RSSI band-sweep (CC1101).** Reads the CC1101's RSSI across the four band presets (315 / 433.92 / 868.35 / 915 MHz) while you hold an unknown remote's button, peak-holding a bar per band and highlighting the strongest — so you learn *which band* a remote transmits on before trying to capture it. Modulation-independent (reads energy, not envelope), so it locates FSK remotes the OOK capture path can't yet demodulate. Field-verified against a tobacco-vending activator and a car keyfob (both correctly placed on 433.92). First phase of slice-0019; FSK demodulated capture follows.

## 2026-07-02 (field-test follow-ups)
- **Auto Hunt attempted-target tracking fixed.** The attempted-BSSID list capped at 16 and `markNetworkAttempted()` silently dropped beyond that, so in any area with >16 APs attempted targets were never recorded → the same targets got re-selected repeatedly and the skipped count only grew on new captures. Now a **128-entry ring buffer** (evict oldest when full, dedup on insert) — tracking never goes deaf, targets cycle. *(Field-confirmed 18-upload/9-handshake sync ran with flat heap: every pre-connect `largest=47092`, no progressive fragmentation — validates the sync design for 20+.)*
- **Handshake History view no longer near-OOMs mid-capture.** Session list stored full `CapturedHandshake` (~1.4KB each, EAPOL buffers never populated for list entries) and `loadSessionHandshakes()` copied the whole buffer (~26KB for 9, resident afterward → attack heap 70K→51K after a peek; History dipped to ~20-30K). New lightweight `SessionHandshakeEntry` (~45B) — ~30× smaller.
- **"Sync all new" count** now shows distinct handshakes (e.g. 9) via `countPendingSyncCaptures()` instead of per-service job count (18 = ×2 services). Sync still runs all uploads; progress box stays per-upload with SSID + service tag.

## 2026-07-02
- **Cloud-sync survives a fragmented post-Auto-Hunt heap without a reboot.** The bulk "Sync all" now purges the 64.8KB canvas for the *whole* run (was: keep it resident + only purge adaptively below a 30KB largest-block floor, which never tripped when the largest block stayed >30KB yet TLS still couldn't place its two 16KB record buffers alongside the canvas → "Connection failed"). WiFi is held up across the run (per-file toggling crashed the stack after ~20 files); the canvas is restored once at the end after WiFi is torn down (per-file restore starved after ~5 files). Added `[Captures] heap` diagnostics (free + largest-block) and a **direct-to-`M5.Display` per-file progress box** so the UI shows live progress while the canvas is purged. Field-confirmed: 2-item sync clean, per-job heap baseline identical (no progressive fragmentation).
- **8-bit RGB332 canvas shipped — ~32KB DRAM reclaimed.** Global canvas dropped from 16bpp (64800 B) to 8bpp RGB332 (32400 B) via one `setColorDepth(8)`; field-confirmed idle free ~98KB → ~128KB. RGB332 quantization was visually fine on all themes except Cyberpunk's background, which flattened to black (its very-dark purples sit below RGB332's first non-zero thresholds) — **retuned the Cyberpunk bg ramp** onto visible RGB332 cells (dark-indigo→purple), field-confirmed good. The exact-colour 8-bit *palette* alternative was scoped ([docs/SPIKE-8bit-canvas.md](docs/SPIKE-8bit-canvas.md)) but not needed. Merged `spike/8bit-canvas-palette` → `feature/hid-menu`.
- **Memory audit — screen list retention.** Finding: all list-holding screens are factory-registered, so ScreenManager `delete`s them on exit and the destructor already frees member vectors — the "vector-capacity-on-`hide()`" pattern mostly *doesn't apply*. The real retention was two other things, now fixed: (1) **session state within a persisting instance** — stopping/restarting Auto Hunt without leaving the screen left the prior run's captures in the list (count reset, list didn't); now reset in `startCapture()`. This is the true cause of the reported stale-history (the earlier `hide()` clear was harmless but misdirected). (2) **singleton lists that outlive the screen** — `ScannerScreen::hide()` now `deinit()`s the `WiFiScanner` AP list (mirrors Wardriving; handoff target is copied into `ScreenParams`) and `BleScannerScreen::hide()` now `clearDevices()` (clear+shrink, frees per-device heap strings) without tearing down NimBLE. Sniffer/captures/whitelist need nothing — destructor covers them.
- **pwncrack results-fetch diagnostic.** Log the numeric HTTP status (was blank — `errorToString()` only maps negative codes) and treat 404 as benign "no potfile yet". Field log confirmed the earlier blank error was a 404, not a heap/connection failure (WPA-SEC fetched fine on the same connection).

## 2026-06-30
- **BadUSB/BadBLE DuckyScript unification (P0–P3)** — USB HID keystroke injection module for the Cardputer's native ESP32-S3 USB-OTG (`USBHIDKeyboard`, HID-on-demand — activating it drops the `/dev/ttyACM` serial console until reboot, an accepted tradeoff). `DuckyInterpreter` shared between the USB path (`BadUsbScreen`) and a new BLE path (`BleBadBleScreen`'s DuckyScript sub-flow, via a `BleHidKeyboard` adapter over the existing `BLESpanner`). SD script loading (`/adversary/badusb/*.txt`) plus 7 built-in scripts. US/ES keyboard layout, persisted in settings. All 33 pre-existing BadBLE quick-actions preserved.
- **Lazy pointer singletons — 17.8 KB static DRAM saved.** Converted ~10 function-local-static singletons (`TrafficProxy`, `StationScanner`, `TvBGoneBlaster`, `HandshakeCapture`, `WardrivingManager`, `GpsManager`, `PacketSniffer`, `Deauth`, and others) to file-scope pointer-based lazy singletons, moving `sizeof(Class)` from link-time BSS to first-use heap allocation.
- **Static lookup tables moved to flash; unnecessary static buffers dropped.** Beacon-spam SSID/lyric lists converted from `const std::vector<std::string>` (heap-allocated at boot) to `static const char* const[]` (flash-resident, on-demand vector construction). Several `static char buf[]` locals in render paths that didn't need to outlive the frame were made stack-local. `ble_spanner.cpp`'s duplicate ASCII→HID mapping tables were deduplicated against the canonical `hid_keycodes::asciiToHid_US/ES` tables (byte-verified identical before switching), removing ~512 bytes of duplicated flash and the divergence risk between the two copies.
- **Confirmed `tvbgone_data.h`'s IR code tables need no PROGMEM migration** — on ESP32, `PROGMEM` is a no-op and `const` data at file scope already lives in flash `.rodata` with zero RAM cost; the tables were already declared this way. The broader "move static data to flash" work above generalized the same principle to other modules' lookup tables.

## 2026-06-29
- **Bulk "Sync all new" upload + second cracking service (pwncrack.org).** Captures screen now has a "Sync all new" action that iterates every not-yet-synced handshake and uploads it to every cracking service with a configured API key — WPA-SEC (`.pcap`) and the new **pwncrack.org** service (`.hc22000`/`.22000`), reusing the existing heap-paced `tls_upload::streamFile()` stack. This also resolves the "`.22000` files are dead on-device" gap noted in the prior backlog pass — pwncrack now consumes them directly. ## 2026-06-25
- **WPA-SEC / WiGLE TLS cert validation** — replaced `client.setInsecure()` on all three upload/fetch paths with `tls_upload::applyCaBundle()`, validating the server against the full Mozilla root-CA bundle embedded in the precompiled mbedTLS lib (`CONFIG_MBEDTLS_CERTIFICATE_BUNDLE_DEFAULT_FULL`, ~68 KB flash, no per-host pin to rotate). Added a pre-TLS time gate (`timeSyncedForTls()`, rejects stale `SD_CACHE`/`NONE` since the Cardputer has no RTC) and multi-server NTP fallback. Hardware-validated: WiGLE upload (incl. 122 KB) + WPA-SEC cracked-results fetch both succeed with validation on, heap healthy.
- **Dashboard path traversal fixed** — `handleNotFound()` now gates the decoded URL path through `path_security::isSafeWebPath()` (rejects `/..`, backslashes, control chars; 400 on reject) before joining to the dashboard dir. Locked in by `test/test_server_security` (6 cases).
- **`dashboardAuthEnabled` defaults to true** — auth-by-default for server mode (struct initializer + settings-load fallback).
- **Heap-paced TLS uploads** — shared `tls_upload::streamFile()` (soft/hard heap floors, drain-on-dip, clean-abort + retry) for WPA-SEC/WiGLE, pre-connect heap gating, and DNS/connect retry with backoff. Hardware-validated.
