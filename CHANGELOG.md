## 2026-09-10
- **Sub-GHz RSSI band-sweep (CC1101).** Reads the CC1101's RSSI across the four band presets (315 / 433.92 / 868.35 / 915 MHz) while you hold an unknown remote's button, peak-holding a bar per band and highlighting the strongest — so you learn *which band* a remote transmits on before trying to capture it. Modulation-independent (reads energy, not envelope), so it locates FSK remotes the OOK capture path can't yet demodulate. Field-verified against a tobacco-vending activator and a car keyfob (both correctly placed on 433.92). First phase of slice-0019; FSK demodulated capture follows.

## 2026-09-08
- **CC1101 sub-GHz jamming.** Carrier-wave or modulated-noise transmission on the selected band preset to hold a channel busy against a fixed-code receiver. Hold-to-jam (emits only while the key is held) behind an interference-warning gate; each burst is chunked so the shared GDO0 keyboard-matrix row is released between bursts and ESC stays responsive. (slice-0017)
- **Modules dashboard + hot-swap re-detection.** A live inventory of attached peripherals (Sub-GHz/2.4 GHz cap, RFID, GPS) with a **Re-scan** action, so a module seated after boot is detected without a reboot — its greyed-out menu tile un-greys as soon as the re-scan finds it. Also surfaces the cap-detection override. (slice-0018)
- **Status bar surfaces the multi-radio cap; RFID badge spelled out.** The resolved cap shows an "RF" badge; the RFID indicator reads "RFID" rather than a terse glyph.
- **RFID and a cap GPS can run together.** Previously RFID was blanket-skipped whenever a cap GPS was present; now both coexist on their separate buses.
- **Browser-based web flasher shipped.** An ESP Web Tools page on GitHub Pages flashes the prebuilt firmware over WebSerial. Includes the **dio-not-qio factory-image fix** (qio bricked the S3 via a boot-loop on the chip-less board), same-origin firmware serving to dodge CORS, and a Pages redeploy dispatched after each release so the flasher tracks the latest build. Web flash observed green on hardware. (slice-0016)
- **Dependencies pinned with a resolved lock snapshot.** Exact versions across all envs (no `^` ranges) plus a `DEPENDENCIES.lock.md` snapshot, so a reinstall can't silently drift the M5/transitive libs.

## 2026-09-06 (initial public release)
- **The Adversary firmware went public.** First public source drop, with CI building every target and running the native test suite on push/PR (slice-0010) and the repository infrastructure for public release (slice-0011). Python pinned to 3.13 for the ESP32 builds; GitHub Actions bumped (checkout/cache/setup-python/codeql).
- **Sub-GHz OOK capture & replay (CC1101).** Raw OOK capture and replay across 315 / 433.92 / 868.35 / 915 MHz via the multi-radio cap, with a pulse-train preview of the captured signal. (First appearance in this log; shipped earlier as slice-0003.)
- **2.4 GHz spectrum analyzer (NRF24).** Channel-occupancy sweep (received-power detection) across the 2.4 GHz band for activity/interference mapping. (slice-0006)

## 2026-07-02 (field-test follow-ups)
- **Auto Hunt attempted-target tracking fixed.** The attempted-BSSID list capped at 16 and `markNetworkAttempted()` silently dropped beyond that, so in any area with >16 APs attempted targets were never recorded → the same targets got re-selected repeatedly and the skipped count only grew on new captures. Now a **128-entry ring buffer** (evict oldest when full, dedup on insert) — tracking never goes deaf, targets cycle. *(Field-confirmed 18-upload/9-handshake sync ran with flat heap: every pre-connect `largest=47092`, no progressive fragmentation — validates the sync design for 20+.)*
- **Handshake History view no longer near-OOMs mid-capture.** Session list stored full `CapturedHandshake` (~1.4KB each, EAPOL buffers never populated for list entries) and `loadSessionHandshakes()` copied the whole buffer (~26KB for 9, resident afterward → attack heap 70K→51K after a peek; History dipped to ~20-30K). New lightweight `SessionHandshakeEntry` (~45B) — ~30× smaller.
- **"Sync all new" count** now shows distinct handshakes (e.g. 9) via `countPendingSyncCaptures()` instead of per-service job count (18 = ×2 services). Sync still runs all uploads; progress box stays per-upload with SSID + service tag.

## 2026-07-02
- **Cloud-sync survives a fragmented post-Auto-Hunt heap without a reboot.** The bulk "Sync all" now purges the 64.8KB canvas for the *whole* run (was: keep it resident + only purge adaptively below a 30KB largest-block floor, which never tripped when the largest block stayed >30KB yet TLS still couldn't place its two 16KB record buffers alongside the canvas → "Connection failed"). WiFi is held up across the run (per-file toggling crashed the stack after ~20 files); the canvas is restored once at the end after WiFi is torn down (per-file restore starved after ~5 files). Added `[Captures] heap` diagnostics (free + largest-block) and a **direct-to-`M5.Display` per-file progress box** so the UI shows live progress while the canvas is purged. Field-confirmed: 2-item sync clean, per-job heap baseline identical (no progressive fragmentation).
- **8-bit RGB332 canvas shipped — ~32KB DRAM reclaimed.** Global canvas dropped from 16bpp (64800 B) to 8bpp RGB332 (32400 B) via one `setColorDepth(8)`; field-confirmed idle free ~98KB → ~128KB. RGB332 quantization was visually fine on all themes except Cyberpunk's background, which flattened to black (its very-dark purples sit below RGB332's first non-zero thresholds) — **retuned the Cyberpunk bg ramp** onto visible RGB332 cells (dark-indigo→purple), field-confirmed good. The exact-colour 8-bit *palette* alternative was scoped ([docs/SPIKE-8bit-canvas.md](docs/SPIKE-8bit-canvas.md)) but not needed. Merged `spike/8bit-canvas-palette` → `feature/hid-menu`.
- **Memory audit — screen list retention.** Finding: all list-holding screens are factory-registered, so ScreenManager `delete`s them on exit and the destructor already frees member vectors — the "vector-capacity-on-`hide()`" pattern mostly *doesn't apply*. The real retention was two other things, now fixed: (1) **session state within a persisting instance** — stopping/restarting Auto Hunt without leaving the screen left the prior run's captures in the list (count reset, list didn't); now reset in `startCapture()`. This is the true cause of the reported stale-history (the earlier `hide()` clear was harmless but misdirected). (2) **singleton lists that outlive the screen** — `ScannerScreen::hide()` now `deinit()`s the `WiFiScanner` AP list (mirrors Wardriving; handoff target is copied into `ScreenParams`) and `BleScannerScreen::hide()` now `clearDevices()` (clear+shrink, frees per-device heap strings) without tearing down NimBLE. Sniffer/captures/whitelist need nothing — destructor covers them.
- **pwncrack results-fetch diagnostic.** Log the numeric HTTP status (was blank — `errorToString()` only maps negative codes) and treat 404 as benign "no potfile yet". Field log confirmed the earlier blank error was a 404, not a heap/connection failure (WPA-SEC fetched fine on the same connection).

## 2026-06-30
- **BadUSB/BadBLE DuckyScript unification (P0–P3)** — USB HID keystroke injection module for the Cardputer's native ESP32-S3 USB-OTG (`USBHIDKeyboard`, HID-on-demand — activating it drops the `/dev/ttyACM` serial console until reboot, an accepted tradeoff). `DuckyInterpreter` shared between the USB path (`BadUsbScreen`) and a new BLE path (`BleBadBleScreen`'s DuckyScript sub-flow, via a `BleHidKeyboard` adapter over the existing `BLESpanner`). SD script loading (`/adversary/badusb/*.txt`) plus 7 built-in scripts. US/ES keyboard layout, persisted in settings. All 33 pre-existing BadBLE quick-actions preserved.
- **Lazy pointer singletons — 17.8 KB static DRAM saved.** Converted ~10 function-local-static singletons (`TrafficProxy`, `StationScanner`, `TvBGoneBlaster`, `HandshakeCapture`, `WardrivingManager`, `GpsManager`, `PacketSniffer`, `Deauth`, and others) to file-scope pointer-based lazy singletons, moving `sizeof(Class)` from link-time BSS to first-use heap allocation.
- **Static lookup tables moved to flash; unnecessary static buffers dropped.** Beacon-spam SSID/lyric lists converted from `const std::vector<std::string>` (heap-allocated at boot) to `static const char* const[]` (flash-resident, on-demand vector construction). Several `static char buf[]` locals in render paths that didn't need to outlive the frame were made stack-local. `ble_spanner.cpp`'s duplicate ASCII→HID mapping tables were deduplicated against the canonical `hid_keycodes::asciiToHid_US/ES` tables (byte-verified identical before switching), removing ~512 bytes of duplicated flash and the divergence risk between the two copies.
- **Confirmed `tvbgone_data.h`'s IR code tables need no PROGMEM migration** — on ESP32, `PROGMEM` is a no-op and `const` data at file scope already lives in flash `.rodata` with zero RAM cost; the tables were already declared this way. The broader "move static data to flash" work above generalized the same principle to other modules' lookup tables.

## 2026-06-29
- **Bulk "Sync all new" upload + second cracking service (pwncrack.org).** Captures screen now has a "Sync all new" action that iterates every not-yet-synced handshake and uploads it to every cracking service with a configured API key — WPA-SEC (`.pcap`) and the new **pwncrack.org** service (`.hc22000`/`.22000`), reusing the existing heap-paced `tls_upload::streamFile()` stack. This also resolves the "`.22000` files are dead on-device" gap noted in the prior backlog pass — pwncrack now consumes them directly. Implemented as chained single-upload cycles (not a monolithic loop) for reliable UI restore between files.

## 2026-06-25
- **WPA-SEC / WiGLE TLS cert validation** — replaced `client.setInsecure()` on all three upload/fetch paths with `tls_upload::applyCaBundle()`, validating the server against the full Mozilla root-CA bundle embedded in the precompiled mbedTLS lib (`CONFIG_MBEDTLS_CERTIFICATE_BUNDLE_DEFAULT_FULL`, ~68 KB flash, no per-host pin to rotate). Added a pre-TLS time gate (`timeSyncedForTls()`, rejects stale `SD_CACHE`/`NONE` since the Cardputer has no RTC) and multi-server NTP fallback. Hardware-validated: WiGLE upload (incl. 122 KB) + WPA-SEC cracked-results fetch both succeed with validation on, heap healthy.
- **Dashboard path traversal fixed** — `handleNotFound()` now gates the decoded URL path through `path_security::isSafeWebPath()` (rejects `/..`, backslashes, control chars; 400 on reject) before joining to the dashboard dir. Locked in by `test/test_server_security` (6 cases).
- **`dashboardAuthEnabled` defaults to true** — auth-by-default for server mode (struct initializer + settings-load fallback).
- **Heap-paced TLS uploads** — shared `tls_upload::streamFile()` (soft/hard heap floors, drain-on-dip, clean-abort + retry) for WPA-SEC/WiGLE, pre-connect heap gating, and DNS/connect retry with backoff. Hardware-validated.
